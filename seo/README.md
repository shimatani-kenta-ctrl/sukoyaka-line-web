# SEO改善（PDCA）の進め方

目的：**集客**（工事の依頼・協力会社の相談）と**採用**（配管工・溶接工の応募）を、検索から増やす。

## 2026年の考え方（キーワードを詰め込むSEOはやらない）

検索はAIが答えをまとめる時代になったため、「検索した人の疑問に、実際に現場を知る会社が、わかりやすく答えている」ことを重視する。
参考：https://blog.formzu.com/seo-strategy-2026

優先する施策：
1. **一次情報**：施工事例（ヒアリングをもとにした実際の工事）、現場写真、代表・職人の言葉。AIや他社には書けない情報を増やす
2. **答えを先に書く**：各ページ・記事の冒頭で結論を示し、AIの要約に引用されやすくする
3. **よくある質問（FAQ）**：発注者・求職者が実際に気にする質問に答え、構造化データ（FAQPage）も付ける
4. **誰が書いているか（E-E-A-T）**：代表のプロフィール・経歴・保有資格（本人確認済みのものだけ）、会社の実在性（住所・地図・Googleビジネスプロフィール）を明示
5. **検索意図ごとのページ設計**：情報を調べる人（例：配管工の仕事内容）／比較する人（例：協力会社の選び方）／依頼・応募する人（お問い合わせ・採用）で、受け皿を分ける。関連ページを内部リンクでつなぐ
6. **指名検索とSNS**：Instagram・Googleビジネスプロフィールと連携し、「健やかライン」で検索される機会を増やす
7. **体験（UX）**：スマホでの読みやすさ、表示速度、迷わない導線

やらないこと：キーワードの詰め込み、中身の薄い記事の量産、AIが書いただけの文章をそのまま公開すること。

## 毎日の流れ（朝7時の自動作業）

1. **Check（確認）**
   - サイトが正常に表示されるか（全ページ）
   - Google にページが登録されているか（site:sukoyaka-line.com）
   - 狙っているキーワード（`keywords.md`）を2〜3個ずつ順番に検索し、順位と競合を確認
   - Search Console のデータを島谷さんから受け取っていれば、それを最優先で分析
2. **Plan（計画）**：確認結果から、その日いちばん効果が見込める改善を1つ選ぶ
3. **Do（実行）**：改善の下書きを作り、GitHub のプルリクエストとして用意する
   （GitHub Pages にはプレビューURLがないため、報告で変更前→変更後を具体的に書く）
4. **Act（報告）**：島谷さんに報告。OKが出たら公開（main に取り込む）

月曜日は、先週の振り返りと今週の重点もあわせて報告する。

## 守ること

- 事実でないことは書かない（施工実績・数字・取引先・資格・お客様の声を作らない）
- 会社情報の正は `src/config/site.ts`、採用条件の正は `src/data/jobs.ts`（ガテン職と同じ内容）
- キーワードを不自然に詰め込まない。読む人の役に立つ文章を優先
- 公開は必ず島谷さんの確認後（プルリクエスト → OK → 取り込み）
- 記録用の変更（このフォルダだけの更新）は、サイトの再公開が走らない設定（deploy.yml の paths-ignore）
